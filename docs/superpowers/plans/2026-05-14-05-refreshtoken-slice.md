# RefreshToken Aggregate — Slice 5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate the `RefreshToken` aggregate end-to-end from the legacy `src/Auth/` layout to the DDD/CQRS architecture under `src/Core/`, keeping the `gesdinet/jwt-refresh-token-bundle` fully functional.

**Architecture:** The bundle requires an entity that implements `RefreshTokenInterface` (setters included). The aggregate implements this interface for compatibility but exposes business-named mutators (`issue`, `revoke`). The bundle's `setX` methods are kept as hydration paths and documented as an intentional interface-compliance compromise. ID is a native `int` (auto-identity), so no custom DBAL type for the ID column — use `<id type="integer">` in XML mapping. RefreshToken does NOT get a UUID-based `RefreshTokenId` VO — it uses an int VO wrapping a non-negative integer.

**Tech Stack:** PHP 8.3, Symfony 7, Doctrine ORM, `gesdinet/jwt-refresh-token-bundle` ^1.3, PHPUnit via Codeception, Symfony Messenger CQRS buses.

- [ ] **Step 2.2: Create RefreshTokenExpiresAtType**

Create `src/Core/Infrastructure/Persistence/Doctrine/DBAL/Types/RefreshTokenExpiresAtType.php`:

```php
<?php

declare(strict_types=1);

namespace App\Core\Infrastructure\Persistence\Doctrine\DBAL\Types;

use App\Core\Domain\Model\VO\RefreshToken\RefreshTokenExpiresAt;
use DateTimeImmutable;
use Doctrine\DBAL\Platforms\AbstractPlatform;
use Doctrine\DBAL\Types\ConversionException;
use Doctrine\DBAL\Types\Type;

final class RefreshTokenExpiresAtType extends Type
{
    public const NAME = 'refresh_token_expires_at';

    public function getSQLDeclaration(array $column, AbstractPlatform $platform): string
    {
        return $platform->getDateTimeTzTypeDeclarationSQL($column);
    }

    public function convertToPHPValue(mixed $value, AbstractPlatform $platform): ?RefreshTokenExpiresAt
    {
        if ($value === null) {
            return null;
        }

        if ($value instanceof RefreshTokenExpiresAt) {
            return $value;
        }

        $dt = \DateTime::createFromFormat($platform->getDateTimeFormatString(), (string) $value);
        if ($dt === false) {
            $dt = date_create((string) $value);
        }

        if ($dt === false) {
            throw new ConversionException("Could not convert '$value' to RefreshTokenExpiresAt.");
        }

        return new RefreshTokenExpiresAt(DateTimeImmutable::createFromMutable($dt));
    }

    public function convertToDatabaseValue(mixed $value, AbstractPlatform $platform): ?string
    {
        if ($value === null) {
            return null;
        }

        if ($value instanceof RefreshTokenExpiresAt) {
            return $value->value()->format($platform->getDateTimeFormatString());
        }

        return null;
    }

    public function getName(): string
    {
        return self::NAME;
    }
}
```

Create `src/Core/Domain/Model/Aggregate/RefreshToken.php`:

```php
<?php

declare(strict_types=1);

namespace App\Core\Domain\Model\Aggregate;

/**
 * BUNDLE COMPATIBILITY COMPROMISE:
 *
 * The gesdinet/jwt-refresh-token-bundle requires an entity that implements
 * Gesdinet\JWTRefreshTokenBundle\Model\RefreshTokenInterface. That interface
 * mandates mutator methods: setRefreshToken(), setUsername(), setValid().
 *
 * DDD principle: aggregates should only expose business-named mutators.
 *
 * Resolution:
 *   - The interface's set* methods are implemented here as bundle hydration paths.
 *     They allow the bundle's RefreshTokenGenerator and Manager to create and
 *     populate tokens during the login/refresh flow without going through our
 *     domain factory — this is an intentional compromise for framework compatibility.
 *   - Our domain code MUST use the static factory `issue()` and the `revoke()` method.
 *   - The set* methods are NOT called by any domain service or application handler.
 *   - The static factory `createForUserWithTtl()` is required by the interface and
 *     used by the bundle during the refresh-token generation on login success.
 *     It sets the internal state directly (bypassing the domain event), as the bundle
 *     controls this flow. The domain event is still fired for our audit/event-bus needs.
 *
 * If the bundle is ever replaced, the set* methods and createForUserWithTtl() can be removed.
 */

use App\Core\Domain\Model\AggregateRoot;
use App\Core\Domain\Model\Event\RefreshToken\RefreshTokenWasIssued;
use App\Core\Domain\Model\Event\RefreshToken\RefreshTokenWasRevoked;
use App\Core\Domain\Model\VO\RefreshToken\RefreshTokenExpiresAt;
use App\Core\Domain\Model\VO\RefreshToken\RefreshTokenId;
use App\Core\Domain\Model\VO\RefreshToken\RefreshTokenValue;
use DateTimeImmutable;
use DateTimeInterface;
use DateTime;
use Gesdinet\JWTRefreshTokenBundle\Model\RefreshTokenInterface;
use Symfony\Component\Security\Core\User\UserInterface;

class RefreshToken extends AggregateRoot implements RefreshTokenInterface
{
    private ?int $id = null;

    private ?RefreshTokenValue $value = null;

    private ?string $username = null;

    private ?RefreshTokenExpiresAt $expiresAt = null;

    private function __construct() {}

    /**
     * Domain factory — use this when issuing a refresh token from domain/application code.
     * Fires RefreshTokenWasIssued event.
     */
    public static function issue(
        RefreshTokenId $id,
        RefreshTokenValue $value,
        string $username,
        RefreshTokenExpiresAt $expiresAt,
    ): self {
        $instance = new self();
        $instance->id = $id->value();
        $instance->value = $value;
        $instance->username = $username;
        $instance->expiresAt = $expiresAt;

        $instance->recordEvent(new RefreshTokenWasIssued(
            id: $id,
            username: $username,
            expiresAt: $expiresAt,
            occurredAt: new DateTimeImmutable(),
        ));

        return $instance;
    }

    /**
     * Required by RefreshTokenInterface — used by the bundle during login/refresh flows.
     * This is a bundle hydration path. Domain code should use issue() instead.
     */
    public static function createForUserWithTtl(string $refreshToken, UserInterface $user, int $ttl): static
    {
        $valid = new DateTime();
        if ($ttl > 0) {
            $valid->modify('+' . $ttl . ' seconds');
        } elseif ($ttl < 0) {
            $valid->modify($ttl . ' seconds');
        }

        $instance = new static();
        $instance->value = new RefreshTokenValue($refreshToken);
        $instance->username = method_exists($user, 'getUserIdentifier')
            ? $user->getUserIdentifier()
            : $user->getUsername(); // @phpstan-ignore-line
        $instance->expiresAt = new RefreshTokenExpiresAt(DateTimeImmutable::createFromMutable($valid));

        // Fire domain event (id is null until Doctrine persists and assigns the auto-increment)
        // We skip the event here because we have no ID yet — the bundle creates the entity
        // before persistence. If an event-bus is needed on issue, hook into Doctrine's
        // postPersist listener instead.

        return $instance;
    }

    /**
     * Domain mutator — revokes the token by setting expiresAt to the past.
     * Fires RefreshTokenWasRevoked event.
     */
    public function revoke(): void
    {
        $this->expiresAt = new RefreshTokenExpiresAt(new DateTimeImmutable('-1 second'));

        $this->recordEvent(new RefreshTokenWasRevoked(
            id: new RefreshTokenId($this->id ?? 0),
            occurredAt: new DateTimeImmutable(),
        ));
    }

    // -----------------------------------------------------------------------
    // RefreshTokenInterface implementation (bundle hydration paths)
    // -----------------------------------------------------------------------

    public function getId(): int|string|null
    {
        return $this->id;
    }

    /** @phpstan-ignore-next-line */
    public function setRefreshToken(string $refreshToken): static
    {
        $this->value = new RefreshTokenValue($refreshToken);
        return $this;
    }

    public function getRefreshToken(): ?string
    {
        return $this->value !== null ? (string) $this->value : null;
    }

    /** @phpstan-ignore-next-line */
    public function setValid(DateTimeInterface $valid): static
    {
        $this->expiresAt = new RefreshTokenExpiresAt(
            $valid instanceof DateTimeImmutable
                ? $valid
                : DateTimeImmutable::createFromInterface($valid)
        );
        return $this;
    }

    public function getValid(): ?DateTimeInterface
    {
        return $this->expiresAt?->value();
    }

    /** @phpstan-ignore-next-line */
    public function setUsername(string $username): static
    {
        $this->username = $username;
        return $this;
    }

    public function getUsername(): ?string
    {
        return $this->username;
    }

    public function isValid(): bool
    {
        return $this->expiresAt !== null && $this->expiresAt->isInFuture();
    }

    public function __toString(): string
    {
        return $this->value !== null ? (string) $this->value : '';
    }
}
```

```php
use Psr\Log\LoggerInterface;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\Routing\Attribute\Route;

#[OA\Tag(name: 'Authentication')]
#[Route('/logout', name: 'app_logout', methods: ['POST'])]
final class LogoutController
{
    public function __construct(
        private readonly CommandBus $commandBus,
        private readonly LoggerInterface $logger,
    ) {}

    public function __invoke(Request $request): Response
    {
        $refreshToken = $request->getPayload()->get('refresh_token');

        if (!$refreshToken) {
            return new Response(
                json_encode(['error' => 'Refresh token required'], JSON_THROW_ON_ERROR),
                Response::HTTP_BAD_REQUEST,
                ['Content-Type' => 'application/json'],
            );
        }

        try {
            $this->commandBus->dispatch(new LogoutCommand(refreshToken: $refreshToken));
            return new Response(null, Response::HTTP_NO_CONTENT);
        } catch (\Throwable $e) {
            $this->logger->error('Logout failed', ['exception' => $e]);
            return new Response(
                json_encode(['error' => 'An error occurred during logout'], JSON_THROW_ON_ERROR),
                Response::HTTP_INTERNAL_SERVER_ERROR,
                ['Content-Type' => 'application/json'],
            );
        }
    }
}
```

## Key architecture decisions documented

### Why setX() methods exist in the aggregate

The `gesdinet/jwt-refresh-token-bundle` calls `setRefreshToken()`, `setValid()`, `setUsername()` via its `RefreshTokenManager` and `RefreshTokenGenerator`. These methods are required by `RefreshTokenInterface`. They are implemented as simple property setters wrapping our VOs. Domain code (application layer and below) must never call these — only `issue()` and `revoke()` are domain-correct.

### Why `id` is a raw `int`, not `RefreshTokenId` VO

Doctrine's IDENTITY generator assigns the `id` after INSERT. During `createForUserWithTtl()` (called by the bundle before persistence), the id is null. Converting to a VO would fail on null. The `RefreshTokenId` VO is used as a parameter type in the `issue()` factory and in events, but internally the aggregate stores the raw int.

### Why no `IssueRefreshTokenService`

The bundle controls the login + token issuance flow entirely via its `AttachRefreshTokenOnSuccessListener`. Our domain's `RefreshToken::createForUserWithTtl()` factory is the entry point for the bundle. No custom service is needed on the issue path.

### The bundle's repository vs ours

The bundle uses its own `RefreshTokenManager` which calls `EntityManager::find()` and `findOneBy()` directly. Our `OrmRefreshTokenRepository` wraps the same EM for domain code (Logout/ForceLogout flows). Both coexist without conflict.

### deptrac and vendor dependency

`App\Core\Domain\Model\Aggregate\RefreshToken` imports from `Gesdinet\JWTRefreshTokenBundle\Model\RefreshTokenInterface`. This violates the "domain has no infrastructure dependencies" principle. It is an intentional, documented compromise. Add to deptrac baseline if it flags it.
